# MI50 / gfx906 本地分支：构建、运行与复用

本分支（`mi50`）是 [lixius/Strata](https://github.com/lixius/Strata) 对上游
[Niko1221/Strata](https://github.com/Niko1221/Strata) 的**本地工作分支**，基线是上游 **v0.1.45**
（`477ac13c`）。它只做三件事：

1. 让 0.1.45 的源码在 **gfx906 + ROCm 7.14 容器 / ROCm 6.3.4 宿主**上**编得过、链得过**；
2. 加上本机实测有效的 **gfx906 V_DOT2_F32_F16 注意力内核**（opt-in，prefill 约 +3–4%）；
3. 把**部署脚本、参数默认值和验证方法**一起放进仓库，换一台同配置的机器可以按本文从零复现。

`main` 保持与上游一致；本分支的提交都在 `mi50` 上，方便 `git rebase` 跟上游。

> 上游的 gfx906 支持是 **opt-in、社区维护**的（`docs/AMD_HIP.md` 写明维护者没有 gfx906 卡）。
> 本分支不是官方发布，默认路径（CUDA / 其他 HIP 卡）不受影响。

## 1. 这套配置

| 项 | 值 |
|---|---|
| GPU | Instinct MI50 32 GB，**gfx906**，60 CU，wave64，无 WMMA / 无 FP4 |
| CPU / 内存 | Ryzen 7 5800X，62.7 GiB |
| 宿主驱动 | ROCm **6.3.4**（`amdgpu` 内核驱动，Ubuntu 24.04 / kernel 6.8） |
| 构建 / 运行容器 | [`mixa3607/rocm-gfx906:7.14-complete`](https://hub.docker.com/r/mixa3607/rocm-gfx906)（HIP 7.14 + gfx906 的 rocBLAS/hipBLAS） |
| 模型 | `Qwen3.8-Flash-Next-GSQ-RCO` **IQ3_S**（2 个 GGUF 分片，`iq_pack.py --experts-bin` 建 pack） |
| 上下文 / KV | `--max-context 262144`，`--kv int8 --kv-resident 32768` |
| 专家缓存 | 引擎默认自适应档（**不要**写 `--adapt-every 0`，MI50 上 decode 会掉 25–53%） |
| MTP | `--spec 4 --spec-min-p 0.7`，`Strata-data/mtp/rt` |

## 2. 相对上游改了什么

| 文件 | 改动 | 为什么 |
|---|---|---|
| `include/strata/platform/hip_compat/cublas_v2.h` | 补 `cublasSgemm` / `cublasGemmStridedBatchedEx` → hipBLAS | 0.1.44 的 `q36_engine.cu` 用了这两个调用，gfx906 的 compat 层只映射了 `cublasGemmEx` |
| `CMakeLists.txt` | gfx906 上跳过 `strata_mmq_w4a4` 目标 | W4A4 是 Blackwell FP4 MMA，gfx906 没有；该 TU 还会去包含 NVIDIA 的 `cuda.h` / `cuda_bf16.h` |
| `CMakeLists.txt` | gfx906 的 `strata_mmq` 追加 `moe_f16_kq.cu` | `moe_fused_iq.cu` 的 HIP 半边无条件引用 `f16kq` 的四个入口，gfx906 分支原本没有这个源，链接会缺符号 |
| `src/kernels/cuda/iq_kernels.cu` | `__shared__ alignas(16)` → `__shared__ __align__(16)`（2 处） | ROCm 6.3.4 / clang 18 不接受 `alignas` 修饰类型 |
| `src/qwen35/q36_engine.cu` | `__ldg(int*)` → 普通读；host 侧 `__half_as_ushort` → `memcpy` 取位 | 6.3.4 的 HIP 头没有 int 的 `__ldg` 重载，`__half_as_ushort` 只有 device 版 |
| `src/kernels/cuda/qsa_decode_attn.cu` | 新增 `attn_chunk_kernel_gfx906`（V_DOT2_F32_F16），`STRATA_GFX906_ATTN_DOT2=1` 启用 | gfx906 没有矩阵核，上游 FP32 内核的瓶颈是 query 的 LDS 读；dot2 把 query 存 fp16、概率存 fp16，微基准 **37.5 → 27.8 ms（−25.8%）**，prefill **+3.1%（4K）/ +4.1%（16K）** |
| `tests/hip/attn_chunk_bench.cpp` + CMake 目标 | dot2 的微基准 / 精度对照 | 不注册 ctest，不影响 `strata` 二进制 |
| `tools/mtp_fetch.py` | 分块下载改为 16 线程（`STRATA_MTP_JOBS`），按 offset 并发写同一文件 | 31 个 MTP 张量散在 28 个分片里，单连接被 CDN 限到 ~0.3 MB/s，8–16 连接约 2 MB/s；SHA256 校验不变 |
| `deploy/mi50/` | 构建 / 启动 / 测速脚本 | 把本机验证过的部署方式固化进仓库 |

> 实验性的 gfx906 IQ 专家 GEMM（`iq_gemm_gfx906` + `mmq_expert_bench` 的 parity/dump）**不在本分支**，
> 在 [`iq-gemm-gfx906`](https://github.com/lixius/Strata/tree/iq-gemm-gfx906) 分支。它还没接入 prefill，
> 属于未完成的工作；本分支保持可构建、可运行的干净状态。

**数值影响**：dot2 把 query 和概率舍入到 fp16，输出与上游 FP32 内核**不逐字节相同**
（`ACB_REF` 对 FP32 dump：bit-identical 0.01%，`max|d| 3.6e-3`，`rms 2.6e-4`，无 NaN/Inf）；
但 32K 与 256K 黄金 prompt 的 **content 5/5 与 0.1.43 逐字节相同**。不想要这个差异就设
`ATTN_DOT2=0`（走上游 FP32 内核）。

## 3. 从零构建

### 3.1 目录布局

脚本默认这套布局（`HOST_ROOT` 可以覆盖，但**仓库目录必须叫 `Strata`**，容器里写死为 `/work/Strata`）：

```
mi50-rocm/                 # HOST_ROOT，容器挂到 /work
├── Strata/                # 本仓库
│   ├── build-714/         # gfx906 构建目录
│   └── third_party/llama.cpp
├── models/                # 容器挂到 /models（只读）
│   └── Qwen3.8-Flash-Next-GSQ-RCO-GGUF-IQ3_S/IQ3_S/*.gguf
└── Strata-data/           # packs / mtp / logs
```

```sh
git clone https://github.com/lixius/Strata.git
cd Strata
git switch mi50
```

### 3.2 pinned llama.cpp

引擎的 ggml 用上游 `setup.py` 固定的 llama.cpp 提交（`LLAMA_CPP_COMMIT`）。不跑 setup 的话手动下载：

```sh
commit=3cf03257f219afbe7334045ff7c6a06ac68c627d
curl -L --fail -o /tmp/llama.zip \
  "https://github.com/ggml-org/llama.cpp/archive/$commit.zip"
mkdir -p third_party
unzip -q /tmp/llama.zip -d third_party
mv "third_party/llama.cpp-${commit:0:7}" third_party/llama.cpp
```

（也可以让 `setup.py` 先下一份，再把 `GGML_SRC` 指向它。）

### 3.3 构建

`deploy/mi50/build.sh` 会创建/复用容器、装 `cmake ninja libstdc++-13-dev`、配置并编译：

```sh
./deploy/mi50/build.sh
# 引擎在跑、内存紧张时：JOBS=4 ./deploy/mi50/build.sh
```

手动等价命令（在容器内，仓库在 `/work/Strata`）：

```sh
docker run -d --name strata714 --network host \
  --device=/dev/kfd --device=/dev/dri \
  --group-add video --group-add "$(getent group render | cut -d: -f3)" \
  --ipc=host --ulimit memlock=-1 --shm-size=16g \
  -v "$PWD/..:/work" -v /path/to/models:/models:ro \
  mixa3607/rocm-gfx906:7.14-complete sleep infinity

docker exec -u "$(id -u):$(id -g)" -e HOME=/tmp -w /work/Strata strata714 bash -c '
  cmake -S . -B build-714 -G Ninja -DCMAKE_BUILD_TYPE=Release \
    -DSTRATA_HIP_GFX906=ON -DCMAKE_HIP_ARCHITECTURES=gfx906 \
    -DSTRATA_GGML_DIR=/work/Strata/third_party/llama.cpp \
    -DCMAKE_C_COMPILER=/opt/rocm/llvm/bin/clang \
    -DCMAKE_CXX_COMPILER=/opt/rocm/llvm/bin/clang++
  cmake --build build-714 --target strata -j "$(nproc)"'
```

注意：

- 必须用 `STRATA_HIP_GFX906=ON`，**不是** `STRATA_ENABLE_HIP`（两者互斥）；
- `-DCMAKE_HIP_ARCHITECTURES=gfx906` 由选项内部强制，写不写都一样；
- 容器里没有 g++，C/C++ 编译器都指向 ROCm 自带的 clang；
- 只编 `strata` 目标即可；`hip_attn_chunk_bench`、`mmq_expert_bench` 在需要时单独编。

### 3.4 Python 环境

服务端和工具需要 numpy / requests：

```sh
python3 -m venv .venv-714
.venv-714/bin/pip install -r requirements.txt
```

容器内路径是 `/work/Strata/.venv-714`（启动脚本默认用它）。

## 4. 运行时数据

### 4.1 模型

IQ3_S 从 [ISTA-DASLab/Qwen3.8-Flash-Next-GSQ-RCO-GGUF](https://huggingface.co/ISTA-DASLab/Qwen3.8-Flash-Next-GSQ-RCO-GGUF)
下载两个分片，放到 `models/Qwen3.8-Flash-Next-GSQ-RCO-GGUF-IQ3_S/IQ3_S/`。国内可用
`HF_ENDPOINT=https://hf-mirror.com`。

### 4.2 pack

```sh
export STRATA_GGUF_PY="$PWD/third_party/llama.cpp/gguf-py"
.venv-714/bin/python tools/iq_pack.py \
  --gguf ../models/Qwen3.8-Flash-Next-GSQ-RCO-GGUF-IQ3_S/IQ3_S/Qwen3.8-Flash-Next-GSQ-RCO-IQ3_S-00001-of-00002.gguf \
  --out ../Strata-data/packs/iq3_s --experts-bin
```

`experts.bin` 约 40–50 GB，需要几分钟。

### 4.3 MTP（可选，但 `--spec 4` 要用）

```sh
.venv-714/bin/python tools/mtp_fetch.py fetch  --out ../Strata-data/mtp
.venv-714/bin/python tools/mtp_pack.py  --src ../Strata-data/mtp --experts q2_0 --out ../Strata-data/mtp/mtp-q2_0.gguf
.venv-714/bin/python tools/mtp_rt.py    --gguf ../Strata-data/mtp/mtp-q2_0.gguf --out ../Strata-data/mtp/rt
cp data/draft_vocab.bin ../Strata-data/mtp/rt/draft_vocab.bin
```

`mtp_fetch.py` 的并发数是 `STRATA_MTP_JOBS`（默认 16；网络差或想限速就设 1）。下载完可
`verify` 校验。没有 MTP 也能跑，去掉启动参数里的 `--spec` 即可。

### 4.4 图像（可选）

```sh
./deploy/mi50/strata-714.sh build-vision
# 再把 mmproj-Qwen3.8-Flash-Next-Q8_0.gguf（或 BF16）放进 models/
```

AMD/HIP 没有 GPU 图像编码器，`-v` 走 CPU（每图约 3–10 秒、常驻 0.7–1.1 GB 内存）。

## 5. 启动

```sh
./deploy/mi50/strata-714.sh -q iq3_s -c 256k -k -d    # 后台启动
./deploy/mi50/strata-714.sh status
./deploy/mi50/strata-714.sh logs
./deploy/mi50/strata-714.sh stop
```

脚本会把配置写到仓库根目录的 `run-iq3_s-ctx256k.json`，用 `serve.server` 拉起引擎
（`backend: hip`，`--kv int8 --kv-resident 32768`，`--conversation-cache-mib 5120`）。

本机验证过的关键默认值（都可以用同名环境变量覆盖）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `PREFILL_CPU_SHARE` | `0` | 0.1.41 在 gfx906 上误开的 CPU 分担；关掉才与 0.1.40.3 逐字节一致 |
| `ROUTE_TAIL_SKIP` | `0` | 0.1.42 误开的尾部专家跳过；会改输出 |
| `ADAPT_OVERLAP` | `0` | 0.1.43 误开的自适应拷贝重叠 |
| `NAN_GUARD` | `1` | #879 非有限 logits 自愈 |
| `PROMPT_F16` | `1` | gfx906 没有原生 BF16，prompt GEMM 走 FP16（prefill 约 +24%） |
| `ATTN_SWIZZLE` / `ATTN_REDUCE12` | `1` / `1` | gfx906 INT8 注意力的 query swizzle / reduce12 |
| `ATTN_DOT2` | `1` | 本分支的 V_DOT2 内核；`0` = 上游 FP32 内核 |
| `CONV_CACHE_MIB` | `5120` | 会话缓存；`0` 关闭 |
| `POOL_WORKERS` / `SPEC` / `SPEC_MIN_P` | `7` / `4` / `0.7` | 本机校准值 |
| `VRAM_RESERVE_MIB` | `1024` | |

**不要**加 `--mmap-experts`（prefill 掉 2.3 倍），也**不要**写 `--adapt-every 0`。

## 6. 验证

```sh
# dot2 微基准：FP32 与 DOT2 各跑一次（INT8 pools）
docker exec -u "$(id -u):$(id -g)" -w /work/Strata strata714 \
  build-714/hip_attn_chunk_bench 8192 2048 3 1
# 本机：FP32 37.5 ms / DOT2 27.8 ms

# 专家 GEMM 对照（IQ3_S 形状）
docker exec -u "$(id -u):$(id -g)" -w /work/Strata strata714 \
  build-714/mmq_expert_bench 40 160 626

# 服务健康检查
curl -fsS http://127.0.0.1:8081/v1/models
```

黄金输出：同一 prompt 在 32K / 256K 下与 0.1.43 的 content 5/5 逐字节相同（dot2 开）；
`ATTN_DOT2=0` 时与上游 0.1.45 的 FP32 路径一致。换参数后至少跑一次
`tools/strata_bench.py`（或 `./deploy/mi50/strata-714.sh bench`）留基线。

## 7. 跟上游更新

`origin` 指向上游，`fork` 指向本仓库：

```sh
git fetch origin
git rebase origin/main mi50
```

已知会冲突的地方：`CMakeLists.txt`、`src/kernels/cuda/qsa_decode_attn.cu`（dot2 的派发点）、
`src/qwen35/q36_engine.cu`（两处兼容补丁）。冲突处理原则：

- 上游若已修好 gfx906 构建，**逐条删掉**对应的兼容补丁，不要叠加；
- dot2 内核保持独立：它只依赖 `STRATA_HIP_GFX906` 和 `gfx906_dot2_attn()` 的运行时判断；
- `mtp_fetch.py` 的并发下载与上游的 SHA256/Range 校验无关，可原样保留。

更新后至少重跑：`build.sh`、`hip_attn_chunk_bench`、32K/256K 黄金输出、`strata_bench.py`。

## 8. 注意

- 本分支的默认**不是**上游默认：`ATTN_DOT2=1` 会改变注意力数值（见第 2 节）。追求与上游逐字节一致时设 `ATTN_DOT2=0`。
- 实验性 IQ GEMM 在 `iq-gemm-gfx906` 分支：只接进 `mmq_expert_bench`，**没有**接入 prefill，
  `STRATA_GFX906_EXPERT_GEMM=1` 尚未实现。`mi50` 分支不包含它。
- 不要把 `build-714/`、`.venv-714/`、`packs/`、`mtp/`、`run-*.json`、benchmark JSON 提交进仓库
  （`.gitignore` 已覆盖）。
- gfx906 在 ROCm 7.x 已没有官方库，只能用社区镜像；宿主驱动与容器 HIP 版本不一致是这套配置的常态，
  本文的构建补丁就是为 6.3.4 宿主编译器准备的。
